# ClauseLock

**Bounty escrow where the terms you read are the terms that execute.**

Bounty prizes are often a promise, not money set aside. Deadlines and payout terms are spread across a listing, an FAQ and the rules, and they can change after you start. ClauseLock fixes the two parts that a chain can actually fix:

1. **Fine Print** (a rules-reading agent, reused from [`../sanity-challenge`](../sanity-challenge)) reads the bounty's rule packet, flags conflicts and missing fields with verbatim, cited clauses, and **refuses to produce terms until the sponsor resolves them**. Its output is a canonical terms document (stable JSON) and its SHA-256.
2. A **Solana program** holds the reward in a PDA. It **derives the terms commitment on-chain** from the executable fields (parties, amount, three deadlines, refund policy, schema version) plus the document digest. The invited contributor accepts by signing that exact hash. No instruction exists that edits terms. Deadlines decide who can move the money, and settlement is permissionless to fixed addresses.
3. Deterministic **`can_*` explainers** answer "why can't I refund?" from on-chain state plus clause IDs.

> **Honest boundary.** The sponsor still decides whether the work is good. If they do not approve before `review_by`, anyone can return the reward to the sponsor. ClauseLock prevents hidden term changes and unfunded promises; it does not guarantee payment for submitted work. This is shown in every terms document (`disclosures`).

Status: devnet-only hackathon prototype (Colosseum Crypto World's Fair). Not audited. Do not use with real funds.

## State machine

```
create_fund ──► Funded ──accept(hash)──► Accepted ──submit_evidence──► Submitted ──approve──► Approved ──finalize_payment──► Paid
                  │  now < accept_by          │  now < submit_by            │  now < review_by      (anyone; to contributor)
                  │                           │                             │
     cancel (sponsor) / finalize_refund   finalize_refund              finalize_refund
     at now >= accept_by                  at now >= submit_by          at now >= review_by      Approved never refunds
                  └──────────────────────────►  Refunded  (anyone; to sponsor)  ◄───────────────┘
```

| Instruction | Signer | Allowed when | Effect |
|---|---|---|---|
| `create_fund(escrow_id, contributor, amount, accept_by, submit_by, review_by, refund_policy, doc_digest)` | sponsor | `now < accept_by < submit_by < review_by`, `amount >= 0.001 SOL`, contributor ≠ sponsor, policy = 0 | creates PDA `["escrow", sponsor, escrow_id_le]`, moves `amount` in on top of rent, computes `terms_hash` |
| `accept(expected_terms_hash)` | invited contributor | Funded, `now < accept_by`, hash equal | Accepted |
| `submit_evidence(evidence_hash)` | contributor | Accepted, `now < submit_by`, hash ≠ 0 | Submitted |
| `approve()` | sponsor | Submitted, `now < review_by` | Approved (irrevocable) |
| `cancel()` | sponsor | Funded (nobody accepted yet) | Refunded |
| `finalize_payment()` | anyone (fee payer) | Approved | reward → `escrow.contributor`; Paid |
| `finalize_refund()` | anyone (fee payer) | Funded & `now >= accept_by`, Accepted & `now >= submit_by`, Submitted & `now >= review_by` | reward → `escrow.sponsor`; Refunded |

**Custody.** The reward sits in the program-owned escrow account on top of its rent-exempt reserve; payouts debit the account directly and the reserve is never touched. The account is not closed: it stays as an on-chain receipt and as replay protection (the PDA for a used `escrow_id` can never be re-created). Destinations are pinned with `has_one`, so a caller cannot redirect funds.

**Time.** `Clock::unix_timestamp` is approximate network time, and execution time counts, not click time. Positive actions use `now < deadline`; expiry uses `now >= deadline`. Tests set the Clock sysvar explicitly in LiteSVM and check each deadline one second before, at, and after.

**Upgrade authority.** Retained during development. A program with an upgrade authority can change behavior regardless of account immutability; the final demo deployment will either be frozen (`--final`) or the retained authority will be disclosed.

## Terms commitment (schema v1)

```
preimage = "CLAUSELOCK_TERMS_V1" | u8 schema_version | sponsor[32] | contributor[32] | u64 escrow_id
         | u64 amount | i64 accept_by | i64 submit_by | i64 review_by | u8 refund_policy | doc_digest[32]   (LE, 157 bytes)
terms_hash = sha256(preimage)
doc_digest = sha256(canonical_json(terms_document))   // sorted keys, no whitespace, 64-bit ints as strings
```

Cross-language test vectors: [`vectors/terms-hash-v1.json`](vectors/terms-hash-v1.json), generated by an independent stdlib-only Python implementation (`scripts/gen_vectors.py`) and checked by both the Rust tests and the TS SDK tests.

## Run it

Toolchain used: Agave/Solana CLI 4.3, `cargo-build-sbf` 4.4 (platform-tools v1.57), Anchor CLI 1.2.0, Rust 1.89 (pinned), Node 20.

```bash
npm install
anchor build --arch v1          # SBPF v1: deployable on devnet today (see note)
cargo test -p clauselock        # 21 LiteSVM tests
npm run test:sdk                # 6 off-chain tests (vectors, gate, doc/chain check, explainers)
npm run typecheck
./scripts/localnet.sh           # local validator + deploy + full demo (about 40 s)
```

CLI:

```bash
npm run terms -- compile --sponsor <PK> --contributor <PK> --escrow-id 1            # exits 2: BLOCKED by the deadline conflict
npm run terms -- compile --sponsor <PK> --contributor <PK> --escrow-id 1 \
     --resolve conflict.demo.deadline=clause.demo.deadline.terms --out terms.json  # emits doc_digest
npm run terms -- inspect --escrow <ESCROW_PDA> --terms terms.json                  # verifies doc + hash, prints can_*
```

Note on SBPF: `cargo-build-sbf` 4.4 defaults to SBPF v3, while `solana-test-validator` 4.x activates SIMD-0500 (no new v0–v2 deploys). Devnet does not have SIMD-0500 active, so the project builds v1 and `scripts/localnet.sh` deactivates that one feature locally to match devnet.

## Demo (3 minutes)

`./scripts/localnet.sh` runs this script, with the deadlines shortened to seconds and labeled `[demo speed]`:
1. Fine Print reads the packet: **BLOCKED**, listing "Deadline: October 14" vs Terms "October 12, 2026, 11:59 PM PT", both quoted with sources.
2. Sponsor resolves (Terms govern); terms document and digest are written to `receipts/`.
3. Sponsor funds escrow A (1 SOL). The account holds reward + rent.
4. Contributor checks the document against the chain and recomputes the hash. Accepting with the hash a UI showing "Oct 14" would produce fails with `TermsMismatch`; accepting the real hash succeeds.
5. Evidence → approve → refund attempt fails with `ApprovedCannotRefund` → a **third wallet** calls `finalize_payment`; contributor +1 SOL; a second payout fails with `WrongState`.
6. Escrow B is never accepted: an early refund fails with `RefundNotYetAvailable`, the explainer says when it opens, and after `accept_by` a third wallet refunds the sponsor.

## What is reused vs new

- **Reused from Fine Print** (`../sanity-challenge`, built earlier for the DEV × Sanity challenge): the content model (`ruleSource` with precedence, `clause` with verbatim quote + `normalized` JSON, `conflict` with claims/resolution), and the "deterministic verdict + clause ids" style of its rule tools.
- **New for ClauseLock:** the Solana program, tests, terms schema and commitment, test vectors, TS SDK, conflict gate and canonical terms document, `can_*` explainers over on-chain state, CLI and demo.
